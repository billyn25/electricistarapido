## Corrección importante de datos estructurados
No se usa Electrician/LocalBusiness porque Google exige una dirección física para la elegibilidad del marcado LocalBusiness y el proyecto no tiene una dirección confirmada. No se inventa una sede. La portada usa Organization + WebSite + Service; las internas usan WebPage.

## Localidades
La portada muestra una selección amplia de municipios de las cinco provincias. Los cinco hubs provinciales ya crean una jerarquía navegable. Las páginas municipales se publicarán por lotes, no como miles de copias.

## Regla para páginas municipales
Cada URL debe aportar utilidad propia y cobertura real:
1. title, H1 y meta description específicos;
2. provincia y municipio correctos;
3. contenido local revisado;
4. síntomas y servicios relevantes;
5. teléfono y WhatsApp;
6. enlaces al hub provincial, servicios y localidades cercanas;
7. canonical propio y sitemap;
8. sin sedes, reseñas, precios, tiempos de llegada, autorizaciones o trabajos ficticios;
9. no crear múltiples páginas casi idénticas para sinónimos del mismo servicio;
10. revisar indexación y rendimiento antes de ampliar el siguiente lote.

## Pendientes antes de considerar el SEO cerrado
- Datos legales reales del titular.
- Dirección física real si se quiere optar al marcado LocalBusiness.
- Logo raster >=112x112 para Organization.
- Search Console: enviar sitemap, inspeccionar portada, 5 hubs y una muestra de servicios.
- Crear páginas municipales en lotes con contenido útil y control de duplicación.
- Incorporar trabajos y reseñas únicamente cuando sean reales y verificables.
- Medir impresiones, CTR, consultas y páginas indexadas por provincia.

## Riesgo que se evita
Google considera doorway abuse y scaled content abuse la generación masiva de páginas geográficas sustancialmente iguales creadas principalmente para captar búsquedas. La arquitectura se construye por utilidad, jerarquía y contenido propio.
